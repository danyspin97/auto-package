# python-cuda-tile

## Build requirements
- The C++ extension needs the CUDA toolkit headers (the CUDA driver header and the NVVM header) at compile time. The CUDA toolkit lookup in the CMake build fails without them, and no toolkit is packaged here, so the package does not compile its extension from source.
- Runtime Requires: typing_extensions.
- The wheel installs a cutile-cache console script, so the package must ship it through the python alternatives components. Add that once, after all flavour installs, because the alternatives macro copies the script per flavour with the shebang rewritten.
Checked against 1.6.0 on openSUSE_Tumbleweed, x86_64.

## Workarounds
- Install the upstream wheel for the build architecture instead of compiling. The CMake build also downloads dlpack and XLA headers over the network when their paths are unset, which fails in the build phase.
- Upstream publishes this version only as per-CPython wheels (cp310 to cp314, plus free-threaded cp314t), with no abi3 or pure-Python wheel. Each Python flavour the package builds for takes the wheel matching its version and flavour.
Checked against 1.6.0 on openSUSE_Tumbleweed, x86_64.
