107. **Several versions of one command (not Python): update-alternatives.** Python executables use libalternatives (section 18 below); this section is the recipe for everything else.
   - Requires in the preamble: `Requires(post): update-alternatives` and
     `Requires(postun): update-alternatives`.
   - %install creates a dummy link target at `/etc/alternatives/<name>`.
   - %post registers the alternative:
       %post
       update-alternatives --install %{_bindir}/x x %{_bindir}/x-impl <priority> || :
   - %postun removes it only when the implementation is gone. Test the file, not `$1`:
       %postun
       if [ ! -f %{_bindir}/x-impl ]; then
         update-alternatives --remove x %{_bindir}/x-impl || :
       fi
     `$1 -eq 0` is wrong here: it breaks a rename, which is an upgrade with a new path.
   - %files lists the link as `%ghost %{_sysconfdir}/alternatives/x`.
   - Priority: bump it when the slaves or the paths change. Keep a dynamic part derived
     from `%{version}` (for example the major version) in the priority, not one fixed number.
   - Scriptlet exit status follows convention 104 (`|| :`).

18. **Console-script entrypoints must use the openSUSE `python_alternative`
   pattern.** If the package declares [project.scripts] or
   entry_points['console_scripts'] in its pyproject.toml/setup.cfg, each script
   MUST use this pattern. Check pyproject.toml or setup.cfg with Read/Grep to
   find all declared scripts, then add ALL SEVEN components below for each
   script named <script>.

   All seven belong together. Some omissions fail the build (a missing
   `%python_clone` leaves `/usr/bin` files unpackaged), others only break
   install or upgrade later (missing scriptlets or `Requires(post)`), so check
   every one even when the build is green.
   For a NEW package write the `libalternatives` form below (gated on
   `suse_version > 1500`, so Tumbleweed uses libalternatives and SLE/Leap 15
   keep update-alternatives); keep whichever form a carried-forward spec uses.

   Component 1 — In %install (after %pyproject_install, one line per script):
     %python_clone -a %{buildroot}%{_bindir}/<script>

   Component 2 — Also at the end of %install (once, not per script):
     %python_expand %fdupes %{buildroot}/%{$python_sitelib}
     (or %{$python_sitearch} for arch packages)

   Component 3 & 4 — Add these package-level requires (once, not per script):
     Requires(post):   update-alternatives
     Requires(postun): update-alternatives

   Component 5 — In %post section (one %python_install_alternative per script):
     %post
     %python_install_alternative <script>

   Component 6 — In %postun section (one %python_uninstall_alternative per script):
     %postun
     %python_uninstall_alternative <script>

   Component 7 — In %files %{python_files} (one line per script):
     %python_alternative %{_bindir}/<script>

   Example for a package with 'khard' script:

     %build
     %pyproject_wheel

     %install
     %pyproject_install
     %python_clone -a %{buildroot}%{_bindir}/khard
     %python_expand %fdupes %{buildroot}/%{$python_sitelib}

     %post
     %python_install_alternative khard

     %postun
     %python_uninstall_alternative khard

     %files %{python_files}
     %{python_sitelib}/khard/
     %{python_sitelib}/khard-%{version}.dist-info/
     %python_alternative %{_bindir}/khard

   Missing %python_clone causes 'Installed (but unpackaged) file(s) found' for
   the /usr/bin/ paths. Missing %python_expand %fdupes leaves duplicate
   files (rpmlint files-duplicate). Missing Requires(post/postun) causes post-install failures. Missing
   %post/%postun causes update-alternatives errors. Missing %python_alternative
   in %files causes file conflicts. The generator often omits some or all of
   these — verify and add all seven.

   **`libalternatives` variant (the form for new packages).** On
   newer openSUSE, `alts`/`libalternatives` is preferred over
   `update-alternatives`; gate the two with a `%bcond`. The `%python_clone`/
   `%python_alternative` macros are unchanged in both modes:
     %if 0%{?suse_version} > 1500
     %bcond_without libalternatives
     %else
     %bcond_with libalternatives
     %endif
     ...
     %if %{with libalternatives}
     BuildRequires:  alts
     Requires:       alts
     %else
     Requires(post):   update-alternatives
     Requires(postun): update-alternatives
     %endif
     ...
     %pre
     %python_libalternatives_reset_alternative <script>
   And in `%check`, when per-flavor tests shell out to the binary itself,
   stage symlinks under `build/flavorbin/` so the tests find each flavor's
   copy:
     %python_flavored_alternatives
     %if %{with libalternatives}
     %{python_expand #
     for b in <script1> <script2>; do
       [ -e build/flavorbin/$b ] || ln -s %{buildroot}%{_bindir}/$b-%{$python_bin_suffix} build/flavorbin/$b
     done
     }
     %endif

   Other forms that are easy to miss:
   - **Multiple scripts under one libalternatives group** —
     `%python_group_libalternatives <script1> <script2> ...` in `%install`
     bundles separate binaries into one group (admin switches them atomically),
     e.g. `sphinx-apidoc sphinx-autogen sphinx-build sphinx-quickstart`.
   - **Aliased scripts in one install/uninstall call** — when upstream ships
     two names for the SAME binary, list both in one
     `%python_install_alternative` call and uninstall only the master:
       %post
       %python_install_alternative pytest py.test
       %postun
       %python_uninstall_alternative pytest
   - **Man pages via alternatives too.** Clone the man page per flavor
     alongside the binary, list the man pages in the same
     `%python_install_alternative` call AFTER the binary names, and declare
     each `%python_alternative %{_mandir}/man1/<name>.1` entry in `%files`:
       %python_clone -a %{buildroot}%{_bindir}/<script>
       %python_clone -a %{buildroot}%{_mandir}/man1/<script>.1
       ...
       %post
       %python_install_alternative <script1> <script2> <script1>.1 <script2>.1
       %files
       %python_alternative %{_bindir}/<script1>
       %python_alternative %{_mandir}/man1/<script1>.1%{?ext_man}
