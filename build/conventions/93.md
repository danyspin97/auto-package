93. **Upstream signatures are verified.** When the release page publishes a
   detached signature next to the tarball (`<tarball>.asc`, `.sig`, `.sign`),
   add it and the maintainer keyring as sources, after `Source0:`:
     Source1:        <tarball-url>.asc
     Source2:        %{name}.keyring
   OBS's source validator then checks the signature itself; no `%prep` code.
   List both URLs in a `download_files` `_service` (convention 92); the keyring
   comes from the key URL upstream publishes (a `KEYS` file, the key linked on
   the release page), written as `<key-url>#/%{name}.keyring`. Never invent or
   guess a key: without a published key URL leave the signature out and say so
   in `reasoning`. A signed checksums file instead of a signed tarball is
   convention 56.
