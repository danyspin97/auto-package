25. rpmlint badness is a budget: the build fails when the TOTAL exceeds 999,
   so the fix is whichever group of files contributes the most, not the first
   error in the log. Find the line `Badness NNNN exceeds threshold 999` and
   read the errors above it with their per-error badness. The usual big
   spenders, in descending order:
   - `wrong-script-interpreter` / `env-script-interpreter` on files that are
     not meant to be executed at all: an installed test suite, test fixtures,
     files with a templated `#!<<PYTHON>>` shebang. Badness 490 each adds up in
     four files. An installed `tests/` directory is not runtime surface: delete
     it in %install:
       %python_expand rm -rf %{buildroot}%{$python_sitelib}/<pkg>/tests/
     A `<pkg>/scripts/` directory is often runtime code (modules the package
     imports, entry points): do not delete it wholesale. Grep the package for
     imports of it first; fix the shebangs of the files rpmlint names
     (convention 46: remove the shebang of a module, `chmod 0755` a real script)
     and delete only files nothing imports or runs.
   - `devel-file-in-non-devel-package` (convention 24), Badness 50 each.
