40. **The `.changes` entry comes from your `changelog` field; write it for a
   reader.** Do not edit or create the `.changes` file and do not run `osc vc`:
   the pipeline adds the entry after a turn that edited the package, from the
   `changelog` field of your reply (never from `reasoning`).
   - It describes the final spec against the PREVIOUSLY PUBLISHED one (what OBS
     had before this run), not against your last attempt: a change made and
     undone across attempts is not in it; an earlier attempt's change that stays is.
   - One bullet per change, one line each in the field, imperative (Add, Drop,
     Fix, Use, Raise, Relax, ...), saying what changed and why: `Relax the numpy
     upper bound to build with numpy 2`.
   - A patch added, removed or refreshed is named by its file name: `Add
     pytest9-fixtures.patch to convert class fixtures to classmethods`. The
     pipeline writes a bullet itself for each patch it refreshed or removed: do
     not repeat those.
   - Bug references (`bsc#N`, `boo#N`, `CVE-YYYY-N`, `gh#owner/repo#N`) are kept
     exactly as written.
   - No build attempts, logs, tools or what you reviewed; no package name, no
     version being packaged, no macros, no `TODO`.
   - The `- Update to X:` line and the upstream changes under it are the
     pipeline's: do not write them.
