27. **ANY dependency missing from OBS is something to BUILD, not something to
   work around.** This is the CORE PRINCIPLE of the packaging system.
   Convention 28 lists the only exceptions.

   Reporting it in `unresolvable_packages` is how it gets packaged: the build
   system queues it, builds it, and retries this package afterwards. Size and
   complexity do not matter. Do not disable a feature or drop a test suite
   merely because its dependency is not in OBS yet.

   This applies to ALL dependency types:
   - **Python packages**: torch, jax, transformers, pydantic — report them ALL
   - **C/C++ libraries**: report the upstream project name, NOT the
     `BuildRequires` string. Strip a leading `lib` and a trailing `-devel`/
     `-dev`: `BuildRequires: libtrantor-devel` is reported as `trantor`,
     `libfoo-dev` as `foo`. The pipeline searches PyPI, then GitHub, by that
     name; the wrapped spelling misses the project and permanently marks the
     dep unbuildable (see "Dependencies that can never be built here" below —
     a dep landing there under a `lib…-devel` spelling is almost always this
     bug; re-report it under the stripped name).
   - **System tools**: cmake, ninja, specialized build tools — report if missing
   - **ANY other dependency**, regardless of type, size, or complexity

   **Check the distro before reporting a C/C++ library as missing.** Package
   names rarely match the library name, and reporting a name that exists under
   another spelling queues a pointless (often huge) source build. First
   `zypper search -s '<guess>*'` and `zypper search --provides --match-exact
   'pkgconfig(<lib>)'` / `'cmake(<Lib>)'`: Arrow is `apache-arrow-devel` and
   `apache-parquet-devel`, not `libarrow-devel` (and python-pyarrow is a
   flavor of the distro's `apache-arrow`). Use the name the distro has
   as the BuildRequires; only when the search finds nothing do you report the
   library in `unresolvable_packages`.

   **Keep the spec honest:** leave all `BuildRequires` in place (Python
   packages, C libraries, system tools) so the build uses them once they
   exist. Never remove a BuildRequires line just because the package is not
   available yet.

   **Special cases, read on demand:** CUDA (never `cuda-devel`/`cuda-runtime`)
   is convention 84; a ctypes/`dlopen` wrapper's `Requires`, a `cffi` pin,
   `ExclusiveArch` propagation and `ninja` are convention 85.
