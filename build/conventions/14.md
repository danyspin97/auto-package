     QUILT_PATCHES is already set to the OBS checkout directory, so patches land
     there automatically. Workflow for each logical fix:
       cd source && quilt new 0001-short-description.patch
       cd source && quilt add path/to/file.py   # BEFORE editing the file
       # Edit source/path/to/file.py using the Edit tool
       cd source && quilt refresh

     headers have wrong line counts and the build dies in `%prep` with
     `malformed patch`. The pipeline applies every `PatchN:` to the pristine
     source before accepting your edit and rolls it back if one fails. Each
     patch must be small and self-contained (one logical fix per patch). After
     creating patches, add them to the spec header using Edit:
       Patch0: 0001-short-description.patch
       Patch1: 0002-another-fix.patch
     %autosetup -p1 in %prep applies them automatically — no %patch lines needed.

     format):**
       # PATCH-{FIX|FEATURE}-{UPSTREAM|OPENSUSE|SLE} <file>.patch [bsc#N|boo#N|gh#owner/repo#N|CVE-YYYY-N] -- <reason>
       # PATCH-FIX-UPSTREAM 0001-fix-fixtures.patch gh#owner/repo#123 -- use classmethod fixtures for pytest 9
       Patch0:         0001-fix-fixtures.patch
     `FIX` is a bugfix, `FEATURE` new behaviour. `UPSTREAM` only with a
     reference you actually read (a commit, PR or issue in the source, PyPI
     metadata, Factory's copy of the patch); `SLE` for a fix only SLE needs
     (convention 89); otherwise `PATCH-FIX-OPENSUSE <file>.patch -- <reason>,
     needs submitting upstream` for a fix upstream should take (a
     Python-version removal, convention 38; a pytest-compat fix, convention 12),
     and plain `PATCH-FIX-OPENSUSE` with the reason for a genuinely
     distro-specific change (this distro's install layout). Bug references are
     kept exactly as written. The same citation discipline applies to
     `%ifarch`-scoped test skips (convention 11). The patch file's own header,
     the `.changes` line and the naming rules are convention 111.

   NEVER state a structural fact about the package (e.g. "has no tests", "uses cmake",

38. **Removed/renamed Python stdlib APIs**: the most common reason an
   upstream test suite or the package's own code fails on Tumbleweed/SLE's
   current Python but passed on whatever upstream last tested against —
   Python removes APIs a release cycle after deprecating them, and many PyPI
   packages lag. This is a source patch (quilt, convention 14), not a spec
   change, and not a missing dependency — do not report these as
   `unresolvable_packages`. Recognize the traceback and apply the replacement:

   | Removed API                                | Symptom                                          | Replacement |
   |---------------------------------------------|---------------------------------------------------|-------------|
   | `pkg_resources` (setuptools, deprecated)     | `ModuleNotFoundError: No module named 'pkg_resources'` or a deprecation warning turned error | `pkg_resources.iter_entry_points(group)` → `importlib.metadata.entry_points(group=group)`; `pkg_resources.get_distribution(x).version` → `importlib.metadata.version(x)` |
   | `distutils` (removed Python 3.12)            | `ModuleNotFoundError: No module named 'distutils'` | `from distutils.X import Y` → the `setuptools`-vendored equivalent, or `sysconfig`/`packaging` for version/platform helpers — check what the specific submodule did before picking a replacement |
   | `imp` (removed Python 3.12)                  | `ModuleNotFoundError: No module named 'imp'`     | `imp.load_source`/`imp.new_module` → `importlib.util` equivalents (`importlib.util.spec_from_file_location` + `module_from_spec`) |
   | `inspect.getargspec` (removed Python 3.11)   | `AttributeError: module 'inspect' has no attribute 'getargspec'` | `inspect.getfullargspec` (closest drop-in) or `inspect.signature` |
   | `unittest.makeSuite` (removed Python 3.13)   | `AttributeError: module 'unittest' has no attribute 'makeSuite'` | `unittest.TestLoader().loadTestsFromTestCase(...)` — or, if it's only used by legacy `if __name__ == '__main__':` scaffolding that pytest never calls, delete that block |
   | `ast.Str`/`ast.Num`/`ast.Bytes`/`ast.NameConstant` (removed Python 3.12) | `AttributeError: module 'ast' has no attribute 'Str'` | All unify into `ast.Constant`; check `.value` instead of `.s`/`.n` |
   | `configparser.SafeConfigParser`/`.readfp` (removed Python 3.12) | `AttributeError: module 'configparser' has no attribute 'SafeConfigParser'` | `SafeConfigParser` → `ConfigParser`; `.readfp(f)` → `.read_file(f)` |
   | `collections.Iterable`/`.Mapping`/`.Callable`/etc. (removed Python 3.10) | `AttributeError: module 'collections' has no attribute 'Iterable'` | Import from `collections.abc` instead of `collections` |
   | `asyncio.get_event_loop()` with no running loop (behavior tightened progressively since 3.10) | `DeprecationWarning`/`RuntimeError: There is no current event loop` | `asyncio.get_event_loop_policy().get_event_loop()` or bare `get_event_loop()` outside a running loop → `asyncio.new_event_loop()` (and `asyncio.set_event_loop()` if the result needs to be the thread's loop) |
   | `unittest` deprecated assertion aliases (removed Python 3.12) | `AttributeError: 'TestCase' object has no attribute 'assertEquals'` (or `assertRaisesRegexp`/`assertRegexpMatches`/`failUnlessEqual` etc.) | Use the modern name: `assertEquals`→`assertEqual`, `assertRaisesRegexp`→`assertRaisesRegex`, `assertRegexpMatches`→`assertRegex`, `failUnless*`/`failIf*`→the plain `assert*` form. A `sed` rename across the test file is usually the whole fix |

   **`versioneer.py` often carries several of these at once**: many packages
   vendor a frozen copy for git-based version detection — if a traceback's
   file is `versioneer.py`, check it for `SafeConfigParser`, `readfp`, or
   other entries in this table before assuming the package's own code is at
   fault.

   This list is not exhaustive — when a traceback names a stdlib module
   attribute that does not exist, treat it as a removal before assuming it is
   package-specific: you have no web search, so Grep the installed stdlib for
   the replacement (`/usr/lib64/python3.*/<module>.py`, or the module's
   directory, for the attribute and its `DeprecationWarning` text) and Factory's
   copy of the package (`osc cat openSUSE:Factory python-<name>
   python-<name>.spec` and its patches) for an existing fix. The fix is almost
   always a one-to-one rename.

94. **A carried-forward patch is rebased with quilt; it is removed only when it is proven applied.**
   - A patch that does not apply to the new source is rebased: `cd source && quilt push -f`, port the `.rej`
     hunks, `quilt refresh --no-timestamps` (plus `-p ab` when the patch's paths start with `a/` and `b/`, `-p 0`
     for a `-p0` patch, `--no-index` when the patch has no `Index:` lines: keep the shape it has), keep its comment header and its `series` line.
     A failing hunk in a test file or a `.result` file is rebased like any other.
     Only a patch that does not apply is yours to rebase. A patch that applies with fuzz is refreshed by the
     pipeline, because rpm applies with `--fuzz=0`. One that applies with an offset only is left byte for byte,
     because rpm applies it: never refresh it.
   - It is removed (spec line, `%patch` line, file, its `series` line) only with a proof that its change is
     already in the new source. The pipeline checks it and rejects a removal without it. Two proofs count:
     `quilt push` of the unchanged patch says `can be reverse-applied`; or, only when quilt says the patch
     fails, every hunk's added lines form one contiguous run, in order, in one file of the new archive, and
     the hunk has a substantive line. "Does not apply", "test only", "obsolete", "probably upstream" are not proof.
     Never disable a patch (commenting out its `PatchN:` or `%patch` line, narrowing `%autopatch`): a patch
     that must stay but cannot be rebased stays applied: in a patch rebase turn you answer it `blocked` with the
     reason, in any other turn you say so in `reasoning` (convention 111). Only a removed `PatchN:` line is checked for the proof today.
   - The pipeline writes the `.changes` bullets for refreshed and removed patches: one `- Refresh a.patch`, or
     one `- Refresh patches:` bullet with a `* name` line per patch when there are several, and
     `- Drop a.patch: already applied upstream (...)`. Do not write them.
   - Prefer quilt; `patch --dry-run` with a relative path is only a read-only fallback, never used to apply.
