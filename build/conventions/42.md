42. **Hardcoded/placeholder version strings need `%{version}` substitution.**
   Distinct from convention 22 (dynamic version *providers* like
   setuptools_scm needing a BuildRequires): here the package's own source
   contains a literal, static version string that is wrong — stale, or a
   placeholder the release process did not template in for a source
   (repository-archive, convention 26) tarball. Symptom: the package builds
   and imports fine but reports its version as `0.0.0`, `0.0.0-dev`, `dev0`,
   `@VERSION@`, or a previous release's number instead of `%{version}` (which
   can also break dependants that check `importlib.metadata.version()` or
   version-gated code paths). Grep for the literal in `setup.py`/
   `pyproject.toml`/a `_version.py` and substitute in %prep:
     sed -i 's/__version__ = ".*"/__version__ = "%{version}"/' setup.py
     sed -i -e '/^version =/s/@VERSION@/%{version}/' pyproject.toml
   Find the exact existing string with Grep first — do not guess the quoting
   or variable name. `%{version}` is a bare value; do not add %python_expand
   or macros around it.
