109. **General packaging rules: no prebuilt binaries, no bundled system libraries, no donation requests.**
   - No prebuilt executables or libraries (`.so*`) in a package: the sources must build
     them. Firmware is handled by the BinaryFirmware policy, and toolchain bootstraps
     need committee approval. A wheel-only release is packaged as-is only where there is
     no source to build from, unless the source cannot be built here (convention 28
     Exception 4, 49: `use_upstream_wheel`; convention 32).
   - No bundled copies of system libraries: patch the package to use the system library
     (convention 91). Do not bundle several upstream projects in one package.
   - The package builds on at least one supported architecture. noarch and content-only
     packages are excepted. Relocatable packages are strongly discouraged.
   - A new application is not packaged when the openSUSE banned-applications list names it.
     You have no web access: the operator checks the list, so do not claim it was checked.
   - Content: nothing pornographic or offensive. Fonts, themes, wallpapers, game levels,
     and sounds or graphics shipped by upstream are fine, and so are examples.
   - No donation requests in summaries, descriptions or comments.
   - A GUI application has a valid `.desktop` file (desktop-entry-spec). `Icon=` is the
     icon's basename without its extension, and `Categories` holds valid categories.
     `%suse_update_desktop_file` is deprecated: do not add it.
   - Every directory the package creates is owned exactly once. A file entry claims
     the file, not its parent. When %install puts files in a new directory under
     %{_datadir}, %{_sysconfdir}, %{_prefix}/lib, %{_libexecdir} or %{_libdir} (for
     example %{_datadir}/wayland-sessions/, %{_datadir}/xdg-desktop-portal/ and its
     portals/), add %dir for each new directory, parents first, or list the directory
     itself with a trailing /. Each %dir line goes directly above the first %files entry
     that lives in that directory, never grouped at the top of the section, and takes no
     comment. auto-package already adds these lines itself, before the build and from the
     check-filelist log after it: check the spec for them before adding one. Never %dir a
     standard directory (%{_bindir}, %{_datadir}, %{_unitdir}): rpmlint
     standard-dir-owned-by-package.
   - A log file owned by a non-root user needs `su <user> <group>` in its logrotate stanza.
   - Udev rules go in `%{_udevrulesdir}`. No udev reload in %post or %postun.
   - Every package produces a useful `-debuginfo`, or the spec says in a comment why it
     is disabled.
   - Shared libraries follow the shared-library policy: a separate `libfoo<soversion>`
     package. Static libraries are discouraged.
   - A web application never installs into `/srv`. An empty directory there is fine.
   - Emacs: one `.el` file goes in `%{_datadir}/emacs/site-lisp`. Several go in a
     subdirectory, with a load-path start file.
   - Fonts go in the system font directories, never in a private application directory.
   - Systemd services follow convention 53.
   - The changelog is the separate `.changes` file (convention 40). Patches follow
     convention 111.
   - Read the rpmlint output. The legacy items (BuildRoot, %clean, %defattr, Group:) are
     handled by lint hygiene and not by an update (convention 90).
   License coverage: the main package's `License:` lists every license of every subpackage, and each file is installed with `%license`.
   - `License:` is an SPDX expression. Short names are used, with `AND`, `OR` and
     parentheses (convention 5).
   - The main package's `License:` lists every license of the spec and of all its
     subpackages.
   - Each subpackage has its own `License:`.
   - Every subpackage that is built from the sources installs the license text with
     `%license` (the file rules are in convention 5 (section 69)).
   - A piece of the tarball that is not shipped, and whose license would otherwise need a
     review, gets a comment for SUSE Legal, placed in the spec:
       # Legal-Review-Notice: <why this piece of the tarball is not shipped>
