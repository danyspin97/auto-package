5. License must be a valid SPDX expression. The generator copies whatever
   PyPI metadata says, which is often unusable:
   - `License: FIXME` means PyPI carried no usable license field. Read
     source/pyproject.toml (`[project] license`), source/setup.py, or the
     LICENSE file itself, and write the SPDX expression it states — e.g.
     `Apache-2.0 WITH LLVM-exception`, `BSD-3-Clause`, `MIT`.
   - Free text that is not SPDX (`BSD-derived (http://www.repoze.org/...)`,
     `Apache Software License`) must be translated. openSUSE also defines
     aliases for licenses with no SPDX id, e.g. `SUSE-Repoze` for the Repoze
     BSD variant; use those rather than inventing an expression.
   - A `License:` field spanning many lines, or containing "Permission is
     hereby granted" / "Apache License" boilerplate, is the whole license text
     dumped into the tag. Replace it with the short SPDX expression (e.g.
     `Apache-2.0`).
   - Also add `%license <file>` to %files naming the actual license file in
     the sdist, if the generator did not (convention 69).
   - **No LICENSE file anywhere in the sdist** (even once you know the SPDX id
     from `pyproject.toml`/PyPI metadata): fetch it from upstream as its own
     source rather than leaving `%license` out (repository URL from the PyPI
     JSON `info.project_urls`; list it in a `download_files` `_service` with
     `mode="manual"`, conventions 82 b and 92). Pin to a tag or commit, not a moving branch:
       Source1: https://raw.githubusercontent.com/<org>/<repo>/<tag-or-commit>/LICENSE
     then in %prep:
       cp %{SOURCE1} .
     so `%license LICENSE` in %files works normally.

69. **`%license` and the licence expression are exact.** Every licence file the
   package ships (`LICENSE*`, `COPYING*`, `NOTICE`, the second and third of a
   multi-licence project) has a `%license` entry. This is the one rule for
   licence files and `*.dist-info/`:
   - Built from a source tree (sdist, repository archive): `%license` the files
     from the source tree (`%license LICENSE COPYING`), never a path inside
     `*.dist-info/`. The dist-info directory entry already ships the copy under
     `licenses/`; a second claim of it fails with 'File listed twice'.
   - A wheel with no source tree: `%license` the dist-info copy and list the
     rest of the dist-info without it:
       %dir %{python_sitelib}/<name>-%{version}.dist-info
       %license %{python_sitelib}/<name>-%{version}.dist-info/licenses/LICENSE
       %{python_sitelib}/<name>-%{version}.dist-info/{METADATA,RECORD,WHEEL,top_level.txt}
     (the files RECORD lists; `%dir` the `licenses/` subdirectory too.)
   The `License:` tag covers what the package ships, not only what PyPI's
   metadata says: a vendored third-party tree (`spdlog`, Rust crates in a cargo
   build) adds its licence, as `Apache-2.0 AND BSD-3-Clause AND MIT`; a statically
   linked LLVM adds `Apache-2.0 WITH LLVM-exception`; redistributable proprietary
   binaries add `AND SUSE-NonFree` (never a `LicenseRef-...` spelling: rpmlint
   `invalid-license`). Read the files in `source/` to decide; when the metadata
   and the shipped licence file disagree, follow the file and say so in a
   comment. The pipeline sends a spec back once when `%files` has no `%license`
   while the source ships a licence file. CUDA/NVIDIA specifics: skill
   nvidia-wheels.

78. **An upstream licence guard asks a question: answer it by checking, never
   by guessing, and never leave the package unbuilt over it.** A build that
   refuses to run until a variable says "this is not a licence violation"
   (`I_CONFIRM_THIS_IS_NOT_A_LICENSE_VIOLATION=1`) wants you to CONFIRM A FACT.
   Read the guard in the source, find the fact it names, and check it (when the
   prompt has a "Licence facts" section, the pipeline has already read the
   recipe's licence lines: that is your evidence, cite it):
   - A guard against shipping an FFmpeg built with GPL or non-free components
     (a CMake check before linking FFmpeg): the distro's FFmpeg is the library
     this package links, so the fact is that it is LGPL-only. Check the FFmpeg
     package's own recipe
     (`osc cat openSUSE:Factory ffmpeg-<N> ffmpeg-<N>.spec`, or the `License:`
     tag from `zypper info`): its `./configure` line has no `--enable-gpl`,
     `--enable-version3` with GPL parts, or `--enable-nonfree`, and its
     `License:` is LGPL. Do not use the S3-download option: the build has no
     network.
   - If the check holds, set the variable in the spec (`export` in `%build`) and
     put this comment on the line above it, with what you read and where:
     `# licence-guard-verified: <the package, the file or tag, the result>` (at
     least a sentence; the pipeline rejects an empty one).
   - If the check fails because the distro's library IS GPL or non-free
     (Factory's `ffmpeg-8` is `License: GPL-3.0-or-later` and configures
     `--enable-gpl`), do NOT give up on the package: have a LICENCE-CLEAN copy
     built in this project. First look whether the project already has one
     (`osc cat <project> ffmpeg-8 ffmpeg-8.spec`, `License:` LGPL and no
     `--enable-gpl`/`--enable-nonfree` in `./configure`): if so, BuildRequire it
     and verify against that spec. Otherwise report the library in
     `patch_dependencies` as `{"name": "ffmpeg-8", "problem": <text>}` (the
     distro SOURCE package name, not the PyPI name), with a problem text that
     says: the recipe must be rebuilt licence-clean (no `--enable-gpl`, no
     `--enable-nonfree`, no component whose licence is GPL-only or non-free,
     taken from the lists in the source's own `configure`), `License:` changed
     to the SPDX expression that is then true, sonames, subpackage names and
     flavors unchanged so dependents still resolve, and the BuildRequires of the
     removed components dropped. In this turn make the rest of your edits but do
     NOT set the confirmation yet: the evidence does not exist until the
     licence-clean copy is built. You are asked again then; read the project's
     recipe (`osc cat <project> ffmpeg-8 ffmpeg-8.spec`), and only if it is
     licence-clean set the variable with the comment above. Never write the
     confirmation on the strength of a copy that is not built.
   - A variable that ACCEPTS TERMS (`ACCEPT_EULA=Y`, `AGREE_*_TERMS`) is a
     person's decision, not a checkable fact: do not set it; build without the
     component the terms guard (option or feature off) or use
     `use_upstream_wheel` when the wheel ships without the guard, and name the
     variable and what it guards in your reasoning.
   Prefer a way of satisfying a guard that needs no override (building against
   the library the guard names, or the upstream wheel) when one exists.
