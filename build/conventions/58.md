58. **Vendored third-party libraries → their LICENSE files must ride
   along in `%license`.** Build backends that need their own dependencies at
   bootstrap time (poetry-core, hatchling, pip itself) ship them vendored
   under `_vendor/`, `_vendored/`, `vendor/`, or `bundled/`. Each vendored
   library's own LICENSE/COPYING must be redistributed (a licence
   requirement; rpmlint does not catch it). Collect them in `%prep` into a
   sibling directory, then list the set with `%license`:

     %prep
     %autosetup -p1 -n <pkg>-%{version}
     mkdir vendoredlicenses
     cp -p src/<pkg>/_vendor/lark/LICENSE          vendoredlicenses/lark.LICENSE
     cp -p src/<pkg>/_vendor/packaging/LICENSE     vendoredlicenses/packaging.LICENSE
     cp -p src/<pkg>/_vendor/packaging/LICENSE.APACHE vendoredlicenses/packaging.LICENSE.APACHE
     ...
     %files
     %license LICENSE vendoredlicenses/*

   Enumerate every subdirectory under `_vendor/` (`ls
   source/src/<pkg>/_vendor/`) and copy one line per LICENSE file, including
   multi-license sets like `packaging/LICENSE{,.APACHE,.BSD}`. Do NOT use `%doc
   _vendor/*/LICENSE`: rpm needs the files out of the Python source tree for
   `%license` tagging. Example: `python-poetry-core`.
   Each vendored library also gets `Provides: bundled(<name>) = <version>` with
   the version read from the vendored copy (its `__version__`, `METADATA` or
   `vendor.txt`), and its licence joins `License:` (convention 91).
