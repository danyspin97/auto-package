51. **`meson-python` / `scikit-build-core` backend arguments go through
   `PIP_CONFIG_SETTINGS`, not direct meson/cmake invocations.** When
   `build-backend = "mesonpy"` or `"scikit_build_core.build"` is in
   pyproject.toml and the package needs a non-default build flag (an
   arch-specific CPU baseline, a feature toggle, a disable for an unavailable
   optional dep), `%pyproject_wheel` runs pip, which only forwards config
   settings to the PEP 517 backend through this env var. Set it in `%build`
   before `%pyproject_wheel`:

     %ifarch x86_64 %{ix86}
     export PIP_CONFIG_SETTINGS="setup-args=-Dcpu-baseline=none"
     %endif
     %pyproject_wheel

   The key is the backend's own name (`setup-args` for meson-python,
   `cmake.define.<VAR>` / `cmake.args` for scikit-build-core — check the
   backend's docs). Multiple settings can be space-separated inside the
   quotes. A bare `-Dfoo=bar` added to `%meson_build` is wrong — that macro is
   not invoked for a PEP-517 build. Example: `python-numpy`.
