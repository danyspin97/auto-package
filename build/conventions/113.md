113. **Standalone Cargo packages: workspaces, arches, `_service` parameters and vendored crates.** The `rust-cargo-packaging` skill has the basics (R1 to R5); this is what it does not cover.
   - A user-facing tool that builds only on the tier-1 arches: `ExclusiveArch: %{rust_tier1_arches}`.
   - Source0 is `%{name}-%{version}.tar.zst`, Source1 is `vendor.tar.zst`. `%autosetup -p1 -a1`
     extracts both; `-a<N>` names the vendor Source number.
   - A workspace: `BuildRequires: cargo-packaging >= 1.2.0`, `%{cargo_build} --all` in
     %build, and one `%{cargo_install -p <crate>}` per binary in %install.
   - `%{cargo_install}` puts binaries in `%{_bindir}` only. Man pages and other files are
     installed by hand with `install -D`.
   - Custom Rust flags go in `%define __rustflags` (for example `--cfg <flag>`).
   - `_service` parameters for `tar_scm`: `versionformat` is `@PARENT_TAG@`, the
     `versionrewrite-pattern` and `versionrewrite-replacement` pair strips the tag prefix, and
     `match-tag` selects the release tag. Then `recompress` to zst and `set_version`.
   - `_service` parameters for `cargo_vendor`: `src`, `compression` zst, and `update`.
     The service carries `mode="manual"` (convention 92). `update` false keeps the upstream
     `Cargo.lock` when a dependency update breaks the build, because upstream CI only ran
     against the old lock. Use `update` true otherwise.
   - `update-crate` in `_service` bumps one crate: `foo@1.2.3`, `foo@recursive`, or
     `foo@1.0+path/Cargo.toml`.
   - Do not use `cargo_prep`: it breaks vendoring (the Fedora and CentOS guidance).
   - A vendored crate is patched last. First use a newer upstream release with a refreshed
     vendor tarball. If that is not possible, either force a newer direct dependency in
     `Cargo.toml`, or pin a sub-dependency as a direct `dep = "=1.4"`, then run
     `cargo vendor --versioned-dirs` (it needs the `.cargo/config.toml` from the `cargo_config`
     file). Or use `[patch.crates-io] dep = { path = "sources/dep" }` with
     `cargo update --offline`. Ship the change as a git-format patch: `BuildRequires: git`
     and `%autosetup -Sgit -p1 -a1`. Patch rules are in convention 111.
