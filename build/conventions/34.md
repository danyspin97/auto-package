34. **Optional extras are `Recommends`, not a build-blocking dependency.**
   Convention 27 says any MISSING package should be built — but that applies
   to dependencies the package actually needs to build, import, or pass its
   test suite. `[project.optional-dependencies]` / `extras_require` often
   lists integrations used only if present at runtime (a faster JSON backend,
   `argcomplete` completion, an alternate driver) that nothing in `%build` or
   `%check` imports. Those get a plain `Recommends:` line — not
   `BuildRequires`, not `Requires`, not `unresolvable_packages` (e.g.
   `python-diffoscope` recommends `python3-argcomplete` and
   `python3-defusedxml`). This is separate from convention 10/15's
   test-dependency handling: extras that ARE imported by `%check` must be
   real `BuildRequires` (Step A: report if missing). Ask which applies:
   - `%check`/`%build` actually imports it → `BuildRequires` (convention 15).
   - Nothing in this build imports it, it only improves behavior for a user
     who installs it later → `Recommends: python-<name>` (flavor-neutral,
     above `%python_subpackages`, convention 65; the plain package name for a
     non-Python tool shelled out to optionally).
     Never add it to `unresolvable_packages` merely because it is missing — a
     `Recommends` on something not yet in OBS does not block the build.
