75. **Version bounds: the one rule.** For `Requires` and `BuildRequires` alike:
   - Minimums upstream declares (`requires_dist`, `[build-system] requires`,
     `find_package(x 1.2)`) are kept as `>=`. Never write a bound you cannot
     quote from the source, and never raise one above the source's own.
   - An upper bound (`<`, `<=`) or an exact `==` pin is kept only when the target
     ships a version that satisfies it (`zypper search -s --match-exact
     python313-<name>`, `zypper info`; this project's own sibling, convention 73).
     Otherwise drop it, keep the minimum (`== 2.11.1` becomes `>= 2.11.1`), and
     put this comment above the line, without a `%`:
       # upstream pins <name><N; builds and tests pass with <shipped version>
     then let `%check` prove it. When the build or `%check` then shows a real
     break, convention 62 applies.
   - One constraint per line (convention 21): a kept range is two lines.
   - A dropped bound is never silent: an upper bound removed without that
     comment hides an ABI or API break from the next maintainer.
