95. **A package whose name carries a version number stays on that series.**
   - `fmt-9`, `boost-1.85`, `wlroots-0_15` and `pipewire0_2` are compat packages: the number in the name is the
     series (`9`, `1.85`, `0.15`, `0.2`) and the package follows only releases of that series, never the newest
     release of the project. `update` skips the package when upstream's newest release is of another series.
   - When the series itself has a newer point release (`wlroots-0_15` 0.15.1 -> 0.15.2), update to the newest
     release of that series, read from the forge's tags. A package on another kind of source stops as "other series".
   - A number that does not start the packaged version (`foo-2` packaging 1.4) is part of the name and pins
     nothing. `libfoo2` (no dash, no underscore) is a soname, not a series.
   - Never rename the package or bump it to the next series: a new series is a new package.
   - A dashed run of two digits with no dot is a major and a minor: `mariadb-55` is 5.5 and `mariadb-100` is 10.0,
     so `mariadb-55` (5.5.46) stays on 5.5.x and `mariadb-102` (10.2.3) on 10.2.x.
   - A package is pinned to its major, not to a series, when its name is its spec's `Name:` plus a series
     (`mariadb-55`, whose spec says `Name: mariadb`: an old-series copy), or when a sibling is on a newer series.
     A sibling is another package of the project whose source is the same forge repository, whatever its name
     (`influxdb` beside `influxdb2`: `influxdb` is pinned, `influxdb2` is not; `zookeeper-kit` counts for
     `zookeeper`). Any other difference from the spec's `Name:` (`python-foo` for `foo`, `foo-kit`, a rename)
     pins nothing. A pinned package takes only releases of its major (of its major.minor for 0.x).
   - A name whose trailing digits are the package's major (`influxdb2` on 2.7.10, `gtk3` on 3.24, `nodejs22` on
     22.11) pins it to that major. A name whose trailing digits are its major and minor written together
     (`python311` on 3.11.4, `libpng16` on 1.6.40) pins it to that minor series. Trailing digits that match
     neither (`bzip2` 1.0.8, `mpg123` 1.x, `lz4` 1.10, `x264` 0.164) pin nothing.
   - A plain package (not pinned) takes a jump of one major. A jump of two or more majors (`couchdb` 1.6.1 ->
     3.5.3) needs the maintainer. So does a move onto a series a sibling is already on, for a package that is
     not held to a series by its name.
