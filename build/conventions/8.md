8. CRITICAL: ALL Python packages MUST be built for multiple Python flavors
   (python311, python312, etc.), not just one. Never write code or comments
   that assume a single Python interpreter. The %python_expand and
   %{python_files} macros handle this automatically (what %python_subpackages is
   for; the generator already sets it up). Do not confuse this (Python
   interpreter flavors) with the OBS *build*-flavor mechanism described next.

   A separate, optional Factory pattern splits testing into its own OBS *build*
   flavor: '%global flavor @BUILD_FLAVOR@%{nil}' with a 'test' flavor that only
   runs %check, '%build'/'%install'/'%files' inside '%if !%{with test}', and
   %check inside '%if %{with test}'.

   **This pattern needs a sibling `_multibuild` file, or it silently does
   nothing.** OBS only instantiates a `%{flavor}` other than the default by
   reading a `_multibuild` file next to the spec:
     <multibuild>
       <package>test</package>
     </multibuild>
   Without it, only the default (non-test) flavor is built, so %check silently
   never executes, with no error. If you introduce this split, create
   `_multibuild` in the same directory as the spec (a brand-new file: use Write,
   per convention 14) in the same step — never one without the other.

   The generator does NOT use this split by default: it runs %check inline in
   the single build, which needs no `_multibuild`. Prefer that; introduce the
   test-flavor split only for a concrete reason (e.g. test-only BuildRequires so
   heavy they bloat the installed package's dependency closure), never as a
   "standard Factory pattern" reflex.

   If you do introduce the split and the test flavor genuinely cannot run on
   some target (a test-only dependency missing on one distro version, e.g. SLE
   vs. Tumbleweed), rather than disabling %check for everyone set
   `ExclusiveArch: do_not_build` inside that specific `%if`/`%ifarch` branch:
   it never matches any real architecture, so OBS skips that one flavor cleanly
   instead of failing:
     %if 0%{?suse_version} <= 1600 && "%{flavor}" == "test"
     # this dependency doesn't exist on this target yet
     ExclusiveArch:  do_not_build
     %endif
   This is the same idiom used to gate a whole subpackage on OBS Staging-ring
   conditions, not a typo for an architecture name.
