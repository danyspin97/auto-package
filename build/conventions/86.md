86. **A carried-forward recipe is the maintainer's: change only what the new release forces, and never fake a dependency.**
   When the spec was carried forward from an older version (the prompt says so),
   an update changes it only where the new release forces a change: every other
   line of the maintainer's recipe stays as it is, hygiene included (convention
   90). Never replace it with a generated
   layout; keep its `Source:` URL, `_service`, subpackage names, `noarch`,
   patches and `%check`. A bundled library the recipe removes
   (`rm -r 3rd_party/x` plus a system `BuildRequires`) stays removed.
   - **Version**: never change `Version:` or the version of the source archive: the
     version is the run's, and the pipeline stops the package when a turn changes it.
   - **SONAME**: follow the one upstream sets. When it changes, rename the
     `lib<name><soversion>` subpackage and list the new soname in `%files`. Never
     pin the old one with `sed`/a patch on `SOVERSION` or a hard-coded `.so.N`.
   - **No stand-ins**: never write a CMake module, `.pc` file, header, stub
     library or Python module in `%prep`/`%build` or as a Source to replace
     something missing or too old, and never `sed` a version or `find_package`
     minimum to pass a check. A missing `Find*.cmake`/`*Config.cmake` means a
     missing or old `-devel`: `BuildRequires` it, or report it (convention 27).
   - **Version bounds**: convention 75. A versioned `BuildRequires` on a system library
     quotes the source's own minimum (`find_package(x 0.9.17)`,
     `PKG_CHECK_MODULES(... >= 1.2)`) in `evidence`. Never write a bound you cannot quote, and
     never raise one above the source's own minimum; if the distro is older, report the
     dependency so it is updated and keep the bound.
   - **Component lists**: after a version jump, and whenever the same error
     returns naming another component (a directory, plugin or test each build),
     compare every component the spec names in `%install`, `%files` and
     subpackages with the new source tree, and fix all of them in one edit.
   - **Header-only libraries** are ONE `noarch` `-devel` package with no base
     `%files` (so no empty base RPM); install its CMake config under `%{_datadir}`.
   - **Inherited problems**: a `%description` that repeats the Summary, or any other
     style problem the origin's spec has too, is left as it is on an update (and on a
     carried dependency): the gate reports it as a warning and does not send the spec
     back. Only a problem this version introduces is fixed.
