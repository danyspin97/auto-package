39. **rpmlint: fix first; an `rpmlintrc` filter only for a reported warning, with
   a reason.** Treat every `E:` line of the rpmlint output as something to fix or
   to filter with a reason, not only a badness over the limit.
   - Fix the cause in the package: `shared-library-not-executable`: `chmod 0755`
     the shared libraries in `%install`, always, vendor libraries included;
     `no-dependency-on python-base`: `Requires: python-base`;
     `devel-file-in-non-devel-package`: convention 24 (never a filter);
     `non-executable-script`: `chmod 0755` or remove the shebang (convention 46);
     `summary-not-capitalized`/`summary-too-long`: fix the Summary (convention 31).
   - A filter is only for what cannot be fixed (a vendor binary without a hash
     section, a bundled library no ldconfig cache applies to, one intentional
     `zero-length` file). It needs all of: a warning OBS actually reported in
     this build log (`unused-rpmlintrc-filter` is itself an error, so start with
     no rpmlintrc); a tight regex naming the warning and the file, unescaped and
     joined with `.*`, paths anchored with `/usr/lib(64)?/python` (the sitearch is
     under `lib64`); and a `# reason:` comment line above it saying why it
     cannot be fixed. Never `setBadness`.
   - A new file is `<name>-rpmlintrc` beside the spec (Write), listed as
     `Source99:       %{name}-rpmlintrc`; an rpmlintrc the package already has
     keeps its name:
       # reason: vendor library shipped prebuilt and stripped, no build to fix
       addFilter("missing-hash-section.*/usr/lib(64)?/python3.*/site-packages/<pkg>/lib/libfoo.so")
   - The file holds only `addFilter(...)` lines, each under its `# reason:` line.
     Never `from Config import *`: rpmlint reads the file the same without it, so
     the line adds nothing.
   - When the last filter goes, drop the `Source99:` line; the pipeline deletes
     the unreferenced file at commit.

25. rpmlint badness is a budget: the build fails when the TOTAL exceeds 999,
   so the fix is whichever group of files contributes the most, not the first
   error in the log. Find the line `Badness NNNN exceeds threshold 999` and
   read the errors above it with their per-error badness. The usual big
   spenders, in descending order:
   - `wrong-script-interpreter` / `env-script-interpreter` on files that are
     not meant to be executed at all: an installed test suite, test fixtures,
     files with a templated `#!<<PYTHON>>` shebang. Badness 490 each adds up in
     four files. An installed `tests/` directory is not runtime surface: delete
     it in %install:
       %python_expand rm -rf %{buildroot}%{$python_sitelib}/<pkg>/tests/
     A `<pkg>/scripts/` directory is often runtime code (modules the package
     imports, entry points): do not delete it wholesale. Grep the package for
     imports of it first; fix the shebangs of the files rpmlint names
     (convention 46: remove the shebang of a module, `chmod 0755` a real script)
     and delete only files nothing imports or runs.
   - `devel-file-in-non-devel-package` (convention 24), Badness 50 each.

31. **rpmlint compliance**: follow rpmlint rules when writing spec files so the
   first build passes. Common issues:

   - **summary-too-long** (Badness: 200): Summary must be a short phrase, not a
     sentence — no trailing period, under ~60 characters when possible.
     - Bad:  `ml_dtypes is a stand-alone implementation of several NumPy dtype extensions used in machine learning`
     - Good: `NumPy dtype extensions for machine learning`

   - **description-line-too-long**: Wrap description lines at 80 characters.

   - **no-manual-page-for-binary**: if the package installs binaries but has
     no man pages, this warning is expected and acceptable.

   - **devel-file-in-non-devel-package**: see convention 24.

46. **Strip a stray shebang from a library file that is meant to ship, don't
   delete the file.** A plain importable module under `%{python_sitelib}`
   can carry a `#!/usr/bin/env python` first line left by upstream. rpmlint
   flags it as `non-executable-script`/`wrong-script-interpreter`, feeding
   convention 25's badness budget — but the file is legitimate library
   content, so remove just the shebang line in `%prep`/`%build`, not
   convention 23/24's "delete the whole file/directory" remedy (that is for
   content that should not ship at all):
     sed -i '1{/^#!/d}' path/to/module.py
   Use a comment like "fix non-executable script". Confirm by Reading the first line of
   the file the rpmlint warning names before patching; don't apply this
   blindly to every `.py` file in the tree. A file that IS meant to be run
   (an installed script with a `__main__` purpose) keeps its shebang and gets
   `chmod 0755` in `%install` instead. Never an rpmlintrc filter for either
   (convention 39).

79. **Check ELF files for rpmlint's errors before the first build.** For a wheel,
   or any package that ships `.so` files: `readelf -d <lib>` and read its
   RPATH/RUNPATH lines (no `| grep`: only `readelf` itself is allowed). A
   RUNPATH with a build-tree path or an empty entry (`$ORIGIN:`) is Badness
   10000 per file and aborts the build. Fix it in `%install`:
   `BuildRequires: patchelf` and `find %{buildroot} -name '*.so*' -type f -exec
   patchelf --set-rpath '$ORIGIN' {} +` (for a source build,
   `-DCMAKE_SKIP_INSTALL_RPATH=ON`), and `chmod 0755` every shared library
   (convention 39). A filter is the last resort, under convention 39's rules
   (`addFilter("binary-or-shlib-defines-rpath.*<file stem>")`). A wheel or
   subpackage whose RECORD lists no `.so` is `BuildArch: noarch`, otherwise
   `E: no-binary`. Headers follow convention 24 (own headers to `-devel`,
   vendored ones deleted). Delete `*.a` archives and test libraries.
