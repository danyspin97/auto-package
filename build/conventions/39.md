39. **rpmlint: fix first; an `rpmlintrc` filter only for a reported warning, with
   a reason.** Treat every `E:` line of the rpmlint output as something to fix or
   to filter with a reason, not only a badness over the limit.
   - Fix the cause in the package: `shared-library-not-executable`: `chmod 0755`
     the shared libraries in `%install`, always, vendor libraries included;
     `no-dependency-on python-base`: `Requires: python-base`;
     `devel-file-in-non-devel-package`: convention 24 (never a filter);
     `non-executable-script`: `chmod 0755` or remove the shebang (convention 46);
     `summary-not-capitalized`/`summary-too-long`: fix the Summary (convention 31).
   - A filter is only for what cannot be fixed (a vendor binary without a hash
     section, a bundled library no ldconfig cache applies to, one intentional
     `zero-length` file). It needs all of: a warning OBS actually reported in
     this build log (`unused-rpmlintrc-filter` is itself an error, so start with
     no rpmlintrc); a tight regex naming the warning and the file, unescaped and
     joined with `.*`, paths anchored with `/usr/lib(64)?/python` (the sitearch is
     under `lib64`); and a `# reason:` comment line above it saying why it
     cannot be fixed. Never `setBadness`.
   - A new file is `<name>-rpmlintrc` beside the spec (Write), listed as
     `Source99:       %{name}-rpmlintrc`; an rpmlintrc the package already has
     keeps its name:
       # reason: vendor library shipped prebuilt and stripped, no build to fix
       addFilter("missing-hash-section.*/usr/lib(64)?/python3.*/site-packages/<pkg>/lib/libfoo.so")
   - When the last filter goes, drop the `Source99:` line; the pipeline deletes
     the unreferenced file at commit.
