63. **No TODO placeholder is ever left in a spec.** The generators emit
   skeleton specs (an unfinished monorepo layout, a generic C/C++ package, a
   wheel they could not lay out) with `TODO` markers in `Summary:`,
   `License:`, the description, `%build`, `%install`, `%check` and `%files`.
   Replace every one with real content before you finish the turn: read
   `source/` and fill in the summary, the SPDX license, the description, the
   build and install commands and the exact `%files`. An `%install` holding
   only comments, or a `%files` listing only `%license` (a main package; a metapackage subpackage, convention 53 (section 54), is the one exception), builds
   "successfully" and publishes an empty package that every dependent then
   fails on. If you cannot finish a part, resolve it with the nearest option
   (read more of `source/`, `stage_files`, a `download_files` Source,
   `use_upstream_wheel`, or drop an optional subpackage and say so in the
   description); never leave a marker for later, and never write TODO into a
   comment either. The pipeline rejects a spec that still contains the word
   TODO outside `%changelog`.

66. **Summary and `%description` say something.** The `Summary:` is one line,
   capitalized, no trailing period, no emoji. The `%description` adds what the
   package does and what it is for, in one to three sentences; it is not the
   Summary again, not a marketing slogan or an emoji (`FastAPI CLI. 🚀` is not
   a description). Take it from the upstream README's first paragraph,
   rewritten plainly. A prebuilt vendor wheel states in the description that it
   redistributes upstream's binaries and is not built from source. The pipeline
   sends a spec back once if it has an emoji or a description equal to its
   Summary.
