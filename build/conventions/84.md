84. **Special case — CUDA at build time means: use the upstream wheel.**
   openSUSE has no CUDA toolkit, so a Python package whose BUILD needs CUDA
   (`find_package(CUDAToolkit)`, `enable_language(CUDA)`, `nvcc`, `.cu` files
   compiled by `ext_modules`/CMake, `#include <cuda*.h>`, linking `libcudart`/
   `libcublas`/`libnccl`) is repackaged from its upstream PyPI wheel
   (convention 28 Exception 4) in the FIRST review turn, not after a failed
   build: return `"use_upstream_wheel"` with `why` quoting the line that proves
   it (one wheel per CPython: convention 49). Never add `cuda-devel`/
   `cuda-runtime` and never report them in `unresolvable_packages`. CUDA used
   only at run time (a JIT compiling `.cu` strings, `dlopen` of a CUDA library)
   is no build-time need: those packages build normally. A package that only
   depends at runtime on a CUDA-needing package keeps its normal build.
   The wheel output, and any `SUSE-NonFree` package, is not Factory or SLE
   material: say so in `reasoning`; it stays out of OSS projects and is never
   submitted. Load skill nvidia-wheels for everything else CUDA/NVIDIA (the
   CUDA Python ecosystem, driver and vendor libraries, headers, licences,
   split wheels, GPU tests).
