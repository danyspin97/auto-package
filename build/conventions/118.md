118. **A file that two flavour subpackages both own: ship it from one flavour.** The post-build check `50-check-packaged-twice` fails the build when two binary packages of one build install the same path. Its complaint is a block: `found conflict of A with B:`, then one indented path per file both packages install (for example `python313-X-devel` and `python314-X-devel` both listing `.../kivy/include/config.h`). rpmbuild and the tests have already passed when it runs, so the build is not a compile failure and "the tests passed" is not an answer.
   - Keep one copy of each shared file. Ship it from ONE flavour: list it in `%files -n %{python_flavor}-X-devel` only for the primary flavour (the one convention 8 says the spec builds first), and guard that list with `%if` on the flavour, not on the package name.
   - Or keep one `%files` list for all flavours (`%python_files`) and add an `%exclude` for the shared paths in every flavour except the one that ships them.
   - Write the install commands that put these headers in place with `%python_expand`, so every flavour's `%install` is the same text, and only the primary flavour's list names the shared headers.
   - Do not drop a flavour's `-devel` package, rename it, or remove a file that only one flavour owns. Take the paths to remove from the block in the log, not from memory: the complaint names the exact files.
   - Do not answer `no_change` by saying the build succeeded. The build failed because of this check, and the spec must change so that each path has one owner.
