24. **Headers: the package's own go to `-devel`, vendored ones are deleted.** This
   is the one rule for `devel-file-in-non-devel-package` (rpmlint error, Badness
   50 per header; thousands of bundled headers blow the 999 budget):
   - The package's OWN installed headers (a C/C++ library's `include/`, the
     public C API of a Python extension that other packages `#include`) go into
     a `%package devel` (convention 53's split; noarch when it holds no ELF).
     Never delete them, never leave them in the main package, never filter them.
   - Headers a Python package or a prebuilt wheel only carries along (vendored
     third-party trees under `data/`, `3rdparty/`, `include/`, a wheel's bundled
     `include/`) are deleted in `%install`, since nothing downstream compiles
     against them:
       %python_expand rm -rf %{buildroot}%{$python_sitelib}/<pkg>/data/
   - Read the rpmlint lines in the build log first and act on the directories
     they name. An rpmlintrc filter is never the answer for headers (convention 39).
   CUDA/NVIDIA specifics: skill nvidia-wheels.
