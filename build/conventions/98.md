98. **Other language ecosystems: Perl, PHP, Ruby, Lua, Lisp.** Each one has its own name, macros and file layout: read the part that matches the package.
   Perl (CPAN) modules: `perl-<Dist-Name>`, built with the perl macros.
   - Name: `perl-<Dist-Name>`, the CPAN distribution name (`perl-Module-Name` for
     `Module::Name`). `cpanspec` writes the first spec; its source may be a
     `download_files` `_service` URL on cpan.
   - A pure Perl module is `BuildArch: noarch`.
   - A license of "same terms as Perl" is written `Artistic-1.0 OR GPL-1.0-or-later`,
     the SPDX form of `Artistic-1.0 or GPL-1.0+` (convention 5).
   - The preamble has `Requires: %{perl_requires}` for the perl version.
   - Install with the macros, then list the files from the generated file list:
       %install
       %perl_make_install
       %perl_process_packlist
       %perl_gen_filelist
       %files -f %{name}.files
       %license <LICENSE file>
       %doc <docs>
   - Do not glob `%{perl_vendorlib}/*`: it also takes each module's `auto/` directory,
     which belongs to the module itself. Use `%perl_gen_filelist`, or
     `%{perl_vendorlib}/*/auto/*` when the list is written by hand.
   - Build and test dependencies are `BuildRequires: perl(Module::Name)`. A non-Perl
     library needed to build goes in as its `-devel` package, by hand. Test
     dependencies are `BuildRequires` too.
   - A man page generated from POD uses the Pod::Man helper (rare).
   - A link that fails under `--as-needed` is fixed by reordering the libraries on the
     link line, or with `export SUSE_ASNEEDED=0`.
   - Legacy, not for a new spec: `BuildRequires: perl-macros` (needed only for
     `suse_version < 1120`), and `perllocal.pod` handling (only for targets before 11.3).
   PHP applications and PEAR packages: their own file layout and names.
   - An application's files go in `/usr/share/php/<app>`. When parallel versions are
     packaged, the directory is versioned: `/usr/share/php/nextcloud13`,
     `nextcloud14_0`.
   - Web-server configuration is in subpackages `<app>-config-apache` and
     `<app>-config-nginx`. Each has `Requires: <app>` and `Supplements: (apache2 and
     <app>)` (the nginx one names `nginx` in place of `apache2`). The main package
     neither requires nor recommends them.
   - `composer.json` is installed as `%doc`. The package does not use it.
   - PEAR package name: `php-pear-<name>`, lower case. The channel package is
     `php-pear-channel-<name>` with `Provides: php-channel(<name>)`.
   - A PEAR package has `BuildRequires: php-devel` and `BuildRequires: php-pear`,
     `Requires: php-pear`, `BuildArch: noarch`, and `Provides: php-pear(<channel>/<package>) = %{version}`.
     An application requires the virtual `php-pear(<channel>/<package>)`, not the
     package name.
   - `Obsoletes: php5-<name>` or `php7-<name>` only when that old name was shipped.
   - Macros: `%__pear`, `%php_pearxmldir`, `%pear_phpdir`, `%pear_docdir`,
     `%pear_testdir`, `%{php_pear_gen_filelist}`. The install step is
     `%{__pear} install --nodeps --offline --packagingroot %{buildroot} package.xml`.
   - `%check` runs phpunit when the source has tests. Never `|| true` just to pass.
   Ruby gems: `rubygem-<name>`, generated with gem2rpm.
   - Create the spec with `gem2rpm -o rubygem-<name>.spec --fetch <name>`. On an update,
     regenerate it from the new gem: `gem2rpm *.gem -o *.spec`.
   - `%install` runs `%gem_install -f`. gem2rpm leaves out the gem `BuildRequires` on
     purpose, and the `Requires` and `Provides` of a gem are generated automatically:
     do not add them by hand.
   - `BuildRequires: ruby-devel` only for a gem with a native extension, one whose
     build fails with `ruby.h` missing.
   - Parallel versions: an old version gets a version suffix (`rubygem-<name>-0_6`)
     only while another package depends on it. On an update, drop the suffix when
     nothing depends on the old one. Exceptions such as rails keep it.
   - A range `>= a, < b` is tightened to `~>` where the gem needs it.
   - When the gemspec has no license, set `License:` by hand (convention 5).
   - Ruby itself is `ruby`, `libruby<N>`, `ruby-stdlib`, `ruby-doc` and `ruby-devel`.
     Do not create a multi-version ruby package (none exists after 13.1).
   Lua modules: `lua<ver>-<module>`, with the Lua macros for the module directories.
   - Name: `lua<ver>-<module>`, for example `lua51-luafilesystem`. Subpackages add the
     `-devel` and `-doc` suffixes.
   - Macros: `%lua_version`; `%lua_archdir` (`%{_libdir}/lua/%{lua_version}`) for a
     compiled module; `%lua_noarchdir` (`%{_datadir}/lua/%{lua_version}`) for pure Lua.
   - Against the luajit headers: in `%build` run
       export LUA_INCLUDE="$(pkg-config --cflags-only-I luajit)"
     and add `BuildRequires: pkgconf-pkg-config`.
   Common Lisp libraries: `cl-<lib>`, installed under `common-lisp`.
   - Name: `cl-<lib>`, unless the name already starts with `cl-`.
   - A pure Lisp library needs no `-devel` package.
   - Sources go in `%{_datadir}/common-lisp/source/<NAME>/`. The `.asd` file is
     symlinked into `%{_datadir}/common-lisp/systems/`.
   - Each implementation package depends on `common-lisp-controller`, registers the
     system in `%post` and unregisters it in `%preun`.
