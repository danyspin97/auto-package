69. **`%license` and the licence expression are exact.** Every licence file the
   package ships (`LICENSE*`, `COPYING*`, `NOTICE`, the second and third of a
   multi-licence project) has a `%license` entry. This is the one rule for
   licence files and `*.dist-info/`:
   - Built from a source tree (sdist, repository archive): `%license` the files
     from the source tree (`%license LICENSE COPYING`), never a path inside
     `*.dist-info/`. The dist-info directory entry already ships the copy under
     `licenses/`; a second claim of it fails with 'File listed twice'.
   - A wheel with no source tree: `%license` the dist-info copy and list the
     rest of the dist-info without it:
       %dir %{python_sitelib}/<name>-%{version}.dist-info
       %license %{python_sitelib}/<name>-%{version}.dist-info/licenses/LICENSE
       %{python_sitelib}/<name>-%{version}.dist-info/{METADATA,RECORD,WHEEL,top_level.txt}
     (the files RECORD lists; `%dir` the `licenses/` subdirectory too.)
   The `License:` tag covers what the package ships, not only what PyPI's
   metadata says: a vendored third-party tree (`spdlog`, Rust crates in a cargo
   build) adds its licence, as `Apache-2.0 AND BSD-3-Clause AND MIT`; a statically
   linked LLVM adds `Apache-2.0 WITH LLVM-exception`; redistributable proprietary
   binaries add `AND SUSE-NonFree` (never a `LicenseRef-...` spelling: rpmlint
   `invalid-license`). Read the files in `source/` to decide; when the metadata
   and the shipped licence file disagree, follow the file and say so in a
   comment. The pipeline sends a spec back once when `%files` has no `%license`
   while the source ships a licence file. CUDA/NVIDIA specifics: skill
   nvidia-wheels.
