91. **Bundled code: unbundle what the distro ships, declare what stays.** When
   the sources carry a copy of another project (`third_party/`, `3rdparty/`,
   `vendor/`, `extern/`, a CMake `FetchContent`/`ExternalProject` target):
   - If the distro ships that library, build against it: the project's own
     system option (`-DUSE_SYSTEM_<X>=ON`, `--with-system-<x>`), or
     `-DFETCHCONTENT_SOURCE_DIR_<NAME>=<dir>` / `find_package`, plus the `-devel`
     in `BuildRequires` (convention 13 for the offline-build side). A copy the
     recipe already removes stays removed (convention 86).
   - A copy that stays (no system package, or a patched fork) gets
     `Provides: bundled(<name>) = <version>`, the version read from the bundled
     tree itself (its `CMakeLists.txt`, `version.h`, `Cargo.toml`, `package.json`),
     never guessed; its licence is added to `License:` (convention 69) and its
     licence file gets a `%license` entry (convention 58).
   - Never ship a bundled copy of a distro library's `.so` under the distro's
     soname without convention 68's `__provides_exclude_from`.
