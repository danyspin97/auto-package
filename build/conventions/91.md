91. **Bundled code: unbundle what the distro ships, declare what stays.** When
   the sources carry a copy of another project (`third_party/`, `3rdparty/`,
   `vendor/`, `extern/`, a CMake `FetchContent`/`ExternalProject` target):
   - If the distro ships that library, build against it: the project's own
     system option (`-DUSE_SYSTEM_<X>=ON`, `--with-system-<x>`), or
     `-DFETCHCONTENT_SOURCE_DIR_<NAME>=<dir>` / `find_package`, plus the `-devel`
     in `BuildRequires` (convention 13 for the offline-build side). A copy the
     recipe already removes stays removed (convention 86).
   - A copy that stays (no system package, or a patched fork) gets
     `Provides: bundled(<name>) = <version>`, the version read from the bundled
     tree itself (its `CMakeLists.txt`, `version.h`, `Cargo.toml`, `package.json`),
     never guessed; its licence is added to `License:` (convention 69) and its
     licence file gets a `%license` entry (convention 58).
   - Never ship a bundled copy of a distro library's `.so` under the distro's
     soname without convention 68's `__provides_exclude_from`.

58. **Vendored third-party libraries → their LICENSE files must ride
   along in `%license`.** Build backends that need their own dependencies at
   bootstrap time (poetry-core, hatchling, pip itself) ship them vendored
   under `_vendor/`, `_vendored/`, `vendor/`, or `bundled/`. Each vendored
   library's own LICENSE/COPYING must be redistributed (a licence
   requirement; rpmlint does not catch it). Collect them in `%prep` into a
   sibling directory, then list the set with `%license`:

     %prep
     %autosetup -p1 -n <pkg>-%{version}
     mkdir vendoredlicenses
     cp -p src/<pkg>/_vendor/lark/LICENSE          vendoredlicenses/lark.LICENSE
     cp -p src/<pkg>/_vendor/packaging/LICENSE     vendoredlicenses/packaging.LICENSE
     cp -p src/<pkg>/_vendor/packaging/LICENSE.APACHE vendoredlicenses/packaging.LICENSE.APACHE
     ...
     %files
     %license LICENSE vendoredlicenses/*

   Enumerate every subdirectory under `_vendor/` (`ls
   source/src/<pkg>/_vendor/`) and copy one line per LICENSE file, including
   multi-license sets like `packaging/LICENSE{,.APACHE,.BSD}`. Do NOT use `%doc
   _vendor/*/LICENSE`: rpm needs the files out of the Python source tree for
   `%license` tagging. Example: `python-poetry-core`.
   Each vendored library also gets `Provides: bundled(<name>) = <version>` with
   the version read from the vendored copy (its `__version__`, `METADATA` or
   `vendor.txt`), and its licence joins `License:` (convention 91).

68. **Bundled shared libraries in a prebuilt wheel must not leak into RPM
   dependencies.** RPM turns every `.so` under site-packages into `Provides:` and
   every `NEEDED` entry into `Requires:`. For a wheel that bundles its own
   libraries, add before `%description`:
     %global __provides_exclude_from ^%{python_sitearch}/.*$
   (use `%{python_sitelib}` for a purelib wheel) so `libavcodec.so.62` or
   `libz3.so.4.15` inside the wheel does not shadow the distro's. Sonames the
   wheel links only through OPTIONAL plugins go into `%global
   __requires_exclude` (`^lib(<name1>|<name2>)\.so.*$`): otherwise installing
   the package drags in a stack for a feature nobody asked for. A wheel
   repaired by auditwheel (a `<name>.libs/` directory, libraries named
   `libavcodec-f34387fd.so.62.11.100` or `libopenblasp-r0-37b5f859.3.3.so`) is
   worse: the `__provides_exclude_from` above removes the Provides of those
   hashed names, yet the auto-generated Requires still name them, so the RPM
   cannot be installed and every package depending on it is `unresolvable`; the
   pipeline's wheel skeleton already writes the `%global __requires_exclude`
   line for it when it sees such libraries (it matches `lib*-<8 hex digits>.so*`
   with at least one letter in the hash, so a date-stamped `libfoo-20240101.so`
   is left alone): keep that line as it is. rpm honours only ONE
   `__requires_exclude`: a second line silently replaces the first, so fold
   every other pattern into the generated regex with `|`
   (`^(<generated pattern without ^ and $>|lib(mpi|ucp)\.so.*)$`) and never add
   another line. For a soname another package of this project supplies,
   exclude the auto-Requires and write the explicit `Requires: python-<that
   package>`, so the choice between flavors is not left to OBS (`have choice
   for lib<x>.so.N`), and add it to `BuildRequires` too when OBS reports that
   choice. Also delete what the runtime does not need from the buildroot in
   `%install`: vendored `include/` headers (convention 24), `*.a` static
   archives, test libraries, and the stubs of another architecture, and list
   the remaining files in `%files` explicitly. `%{_prefix}/external` and other
   non-FHS directories are not created. A copy of a library that stays bundled
   also gets `Provides: bundled(<name>) = <version>` (convention 91).
   CUDA/NVIDIA specifics (NVSHMEM's plugin sonames, `libnccl.so.2`): skill
   nvidia-wheels.

71. **A package the distro already ships is not shipped twice.** Before you finish
   a package, check that no Factory package installs the same files:
   `zypper search -s '*<import name>*'` (and `zypper what-provides
   'python3dist(<name>)'`) and, for a hit, `osc cat openSUSE:Factory <pkg>
   <pkg>.spec` and compare its `%files` module directory with yours (`osc ls`
   is not available to you). When both install the same directory (`python-z3`
   and `z3-solver`'s `z3/`) the two cannot be installed together: add
   `Conflicts: python-<other>` above `%python_subpackages` (the macro makes it
   per flavor) and say in the description that it is a fork or a bundled copy,
   or (usually the right answer) depend on the distro package instead
   (BuildRequires and Requires it, drop this package's copy, name the distro
   package in your reasoning). A bundled copy of a distro library
   (`libz3.so`) also needs convention 68's `__provides_exclude_from`.
