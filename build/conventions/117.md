117. **A stale `_service` source: move its revision to the new tag, never answer no_change.** The `_service` next to the spec fetches the source. When the build log says `service run failed for service 'tar'` or `Error while moving from '<a>' to '<a>-<version>'`, its source service still fetches the OLD release (a `tar_scm`, or an `obs_scm` with a `tar` service), so the archive has no directory for the new version.
   - Edit the `revision` parameter of that source service and nothing else in the source: set it to the tag of the version the spec names, in the form the old value had (`v1.3.7` becomes `v1.4.0`; `1.3.7` becomes `1.4.0`). Keep a placeholder (`@PARENT_TAG@`) as it is: OBS then takes the newest tag. On an `obs_scm` source, a literal `versionformat` that equals the spec's `Version:` exactly becomes `@PARENT_TAG@`, as the update does; any other literal is left alone.
   - Keep the `Version:` line. A fix turn does not change it, and a tag that gives another version when OBS builds it is refused.
   - Do not add or change a service's `mode` or add a service here (convention 86 keeps a carried-forward recipe's services). Only `_service` parameters the pipeline allows are accepted (`osc/service.rs`, `SERVICE_PARAMS`): `download_url` is refused, and so is any host the sandbox does not allow.
   - Do not write the tarball, its `.obsinfo` or a `SourceN:` by hand. The services make them when the package is built, and the pipeline runs them before the build.
   - Your sandbox has no sources and cannot fetch the tag, so you cannot prove the tag exists. That is not a reason for `no_change`: move the revision, name the tag you used and say `unverified` in `reasoning`, and answer `edited`. Answer `no_change` only when the log names a different failure, or the revision already names the tag the spec's `Version:` gives.
   Example: a log line `Error while moving from 'nvme-stas' to 'nvme-stas-3.1'` with `<param name="revision">v3.0</param>` in the `tar_scm` service of a spec with `Version: 3.1` becomes `<param name="revision">v3.1</param>`.
