104. **RPM scriptlets, system users, XML catalogs and SysV init scripts.**
   - Every scriptlet exits 0. Append `|| :` to a command that may fail, or end the
     section with `:`. A scriptlet that fails blocks the whole package transaction.
   - `$1` is the number of instances left after the action:
       %pre and %post on install: 1; on upgrade: 2. Test an upgrade with `-gt 1`, not `-eq 2`.
       %preun and %postun on upgrade: 1; on uninstall: 0.
       %posttrans: `$1 == 1`.
   - Order on an upgrade: %pretrans (new), %pre (new), install, %post (new), %preun
     (old), removal of the old files, %postun (old), %posttrans (new).
   - `-p <interpreter>` names the interpreter. A bashism needs `-p /bin/bash`.
   - A shared library's cache is updated with `%post -p /sbin/ldconfig` and
     `%postun -p /sbin/ldconfig`; in a subpackage, `%post -n <sub> -p /sbin/ldconfig`.
     With `-p`, the section must be completely empty: not even a comment. Otherwise
     ldconfig gets an argument it does not expect ("relative path `0' used to build cache").
   - The `%ldconfig_scriptlets` macro expands to the two `-p /sbin/ldconfig` sections above.
     For current Factory, do not add it (or those sections) to a new spec: file triggers run
     ldconfig. A carried-forward spec keeps the form it has. The spec tidy pass keeps an
     existing `%ldconfig_scriptlets` section in order (`build/src/spec_tidy.rs`); it adds none.
   - MIME, desktop and icon caches: `%mime_database_post`/`%mime_database_postun`,
     `%desktop_database_post`/`%desktop_database_postun` and
     `%icon_theme_cache_post`/`%icon_theme_cache_postun` are needed only for Leap 42.3
     and older. Tumbleweed uses RPM file triggers: do not add them.
   - Texinfo: `Requires(post)` and `Requires(preun): %{install_info_prereq}`, then
     `%install_info --info-dir=%{_infodir} %{_infodir}/%{name}.info.gz` in %post and
     `%install_info_delete` with the same info file in %preun. No scrollkeeper calls.
   - GConf schemas: disable the schema install in %install (`GCONF_DISABLE_MAKEFILE_SCHEMA_INSTALL=1`
     or `--disable-schemas`), run `gconftool-2 --makefile-(un)install-rule` in %pre on
     upgrade, %post, and %preun on removal, and list each `.schemas` file in %files, no glob.
   - Debugging a failing scriptlet: temporarily use `%post -p "/bin/bash -xv"`, and
     remove `-xv` once the fix is in.
   - Migration and configuration work (key generation, database upgrades) does not go in a
     scriptlet. It goes in a systemd unit helper (`ExecStartPre`) or a first-run tool, so
     that containers work.
   Users and groups: declared with sysusers.d, in a `system-user-<name>` package.
   - Provide `Provides: user(<name>)` or `Provides: group(<name>)`. They go in a
     `system-user-<name>` package, or in the main package when no other package needs the user.
   - `BuildRequires: sysuser-tools`, and `%sysusers_requires` in the preamble.
   - Generate the `%pre` file list from the conf source, and load it in %pre:
       %sysusers_generate_pre %{SOURCE1} <name> <name>.conf
       %pre -f <name>.pre
     Install the conf file into `%{_sysusersdir}`.
   - The shell is `-`, never `/bin/false`. A home directory is owned by the package, for
     example `/var/lib/<NAME>`.
   - The package never removes users or groups.
   - A group without a user has only a `g` line in the conf.
   - Do not require `sysuser-shadow` by hand.
   XML catalog entries: a subcatalog under `catalog.d`; the main catalog is never touched.
   - The package's identifiers go in `/etc/xml/catalog.d/<package>.xml`, a `<group>` holding
     them. Install it as `%config %{xml_sysconf_dir}/catalog.d/%{name}.xml`.
   - Never edit `/etc/xml/catalog` or `/etc/xml/catalog-d.xml`.
   - `Requires: sgml-skel >= 0.7`, plus `Requires(post)` and `Requires(postun)` on it.
   - `%post` and `%postun` run `update-xml-catalog`.
   - Schemas go in `%{_datadir}/xml/<name>/schema/` under `rng`, `nvdl`, `sch` or `xsd`.
   - Test an identifier with `xmlcatalog /etc/xml/catalog "<public id>"`.
   SysV init scripts are deprecated: never add one. Use a systemd unit (convention 53).
   - A package that already has an init script keeps it on update. Lint may suggest a
     systemd unit, but it must not remove the behaviour the init script gives.
   - Reference for old releases only, never for a new spec on a current target:
     - LSB header between `### BEGIN INIT INFO` and `### END INIT INFO` with Provides,
       Required-Start, Required-Stop, Should-Start, Should-Stop, Default-Start,
       Short-Description and Description.
     - Scriptlets `%fillup_and_insserv`, `%stop_on_removal`, `%restart_on_update` and
       `%insserv_cleanup`.
     - The init file goes in `%{_initrddir}` with mode 0755, is not `%config`, and has an
       `rc<name>` symlink in `%{_sbindir}`.
