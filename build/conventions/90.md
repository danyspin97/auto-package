90. **Spec hygiene: no obsolete constructs, keep the header.** A spec never
   carries `Group:`, `BuildRoot:`, a `%clean` section, `%defattr(...)` in
   `%files`, `rm -rf %{buildroot}` (or `$RPM_BUILD_ROOT`) at the top of
   `%install`, or `%if 0%{?suse_version} < 1315` (or older) branches: no
   supported target reads them. Do not write them in a new spec; in a
   carried-forward spec drop them in the same edit as a change you make anyway,
   with one `changelog` bullet `Clean up obsolete spec constructs` (never on an
   SLE/Leap maintenance update, convention 89).
   Keep the copyright/licence comment header at the top of the spec as it is.
   Every spec has a `URL:` (the project's home page or repository) and a
   `License:` that is a valid SPDX expression (convention 5).
