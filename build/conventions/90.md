90. **Spec hygiene: no obsolete constructs in a new spec, keep the header.**
   `Group:`, `BuildRoot:`, a `%clean` section, `%defattr(...)` in `%files`,
   `rm -rf %{buildroot}` (or `$RPM_BUILD_ROOT`) at the top of `%install`, and
   `%if 0%{?suse_version} < 1315` (or older) branches are obsolete: no supported
   target reads them. Do not write them in a new spec. An existing spec keeps
   them on an update (convention 86), unless a build or rpmlint failure of this
   version forces the change (for instance a `%defattr` that rpmlint or
   check-filelist rejects). `auto-package lint` removes them from an existing
   spec, in its own commit, and never changes the version: the `Group:` and
   `BuildRoot:` tags, a `%clean` that only removes the build root, the build
   root removal that starts `%install`, the default `%defattr(-,root,root)` of
   a `%files` list, and a hand-written `%post`/`%postun` pair that only runs
   `/sbin/ldconfig` (it becomes `%ldconfig_scriptlets`, but only for a target
   that defines that macro: Tumbleweed, Slowroll, Factory, Leap 16 or SLE 16;
   for any other target the pair stays and lint says so once). Each of those
   inside an `%if` block stays as it is, and so does any other `%defattr`
   mode, and a default `%defattr` that follows a `%attr` or another mode in
   the same `%files` list.
   Keep the copyright/licence comment header at the top of the spec as it is.
   Every spec has a `URL:` (the project's home page or repository) and a
   `License:` that is a valid SPDX expression (convention 5).

41. **Obsolete build/test-runner shims in `setup.py`/`setup.cfg` — delete, do
   not package.** Some entries in `install_requires`/`setup_requires`/
   `tests_require` are leftovers from an older Python ecosystem and are
   never worth adding as a BuildRequires:
   - `pytest-runner` in `setup_requires` — deprecated since 2019. Delete it
     from the source:
       sed -i '/pytest-runner/d' setup.py
     (In an edit that also adds a patch this `sed -i` is refused: put the change in the
     patch, convention 111.)
   - `nose` — unmaintained since ~2015, incompatible with current Python (it
     hits several convention 38 stdlib removals itself). A test suite that
     imports `nose` needs a source patch converting it to plain
     `unittest`/`pytest` idioms, not a `nose` BuildRequires:
       sed -i '/nose/d' setup.py
   - `argparse`, `typing` as plain (non-versioned-backport) entries in
     `install_requires` — stdlib since Python 2.7 / 3.5; always Python-2-compat
     cruft. Delete the line rather than adding a BuildRequires.
   Symptom: `pip`/the build backend's dependency resolution fails, or the log
   shows a package trying to fetch one of these during `%build` (no network
   there — convention 91 (section 13), the network-in-%build pattern) although nothing in the
   package's own code imports it.
