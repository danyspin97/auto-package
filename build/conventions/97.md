97. **Meson projects (a native meson.build, not a Python package built by mesonpy): use the meson macros.**
   - BuildRequires `meson` and the compiler the project needs (`gcc-c++` for C++).
   - Use the macros, not the tool: `%meson` (extra options as `-D<option>=<value>`) in
     place of a bare meson call, `%meson_build` in `%build`, `%meson_install` in
     `%install`, `%meson_test` in `%check`. Do not call `%__meson` directly.
   - Shared libraries: the `libX.so.*` runtime files go in the main package; the
     `libX.so` link and the headers go in `-devel` (convention 32, skill
     plain-c-cpp-packaging).
   - Subprojects (`subprojects/*.wrap`) are bundled code (convention 91). Upstream is
     asked to allow the system library, and the request is named in your reply. Until
     then, a subproject that cannot be replaced ships from its wrap tarball, one
     `SourceN` per tarball, unpacked in `%prep`:
       Source1:  <name>-<version>.tar.gz
       %prep
       mkdir -p subprojects/<name>
       tar -C subprojects/<name> --strip-components=1 -x -f %{SOURCE1}
       %build
       meson subprojects packagefiles --apply
       %meson_build
     `meson subprojects packagefiles --apply` runs at the start of `%build`, before
     the build itself.
