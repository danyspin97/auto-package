89. **SLE, Leap and maintenance targets.** When the target project is an SLE or
   Leap codestream (`SUSE:SLE-*`, `openSUSE:Leap:*`, an `:Update` or maintenance
   project) or the spec gates on `%sle_version`/`0%{?suse_version} < 1600`:
   - Change as little as possible: fix the reported problem with a backported
     patch, and never change `Version:` yourself: the version is the run's (convention 86), and the
     pipeline stops the package when a turn changes it.
     Never rename the package or a subpackage, drop a subpackage, `Provides:` or
     soname, or raise a dependency the codestream does not ship.
   - Every change that gets a bullet cites its bug: `bsc#N` (or `CVE-...`) in the
     patch tag (convention 111, `PATCH-FIX-SLE` for an SLE-only fix) and in the
     `changelog`. A dependency change made for the fix is covered by the fix's
     bullet.
   - Check the codestream's versions, not Tumbleweed's: `zypper` on this host
     reflects Tumbleweed; read the codestream's own spec with `osc cat <project>
     <pkg> <pkg>.spec`. Keep `%{?sle15_python_module_pythons}` and every
     `%if 0%{?suse_version}`/`%sle_version` branch that still selects a live target.
   - No spec cleanup (convention 90) on a maintenance update: only the fix.
